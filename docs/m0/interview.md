# H-2 ヒアリング台本（n=10）

**実施タイミング**：12〜14日目
**対象**：続いた人5人 / 途中で止まった人5人 — **必ず両方**
**時間**：1人10〜15分。通話でもテキストでもよい

---

## 進め方の原則

- **誘導しない。** 「他の人の見るの楽しかった？」と聞いた時点で、H-2 の検証は失敗する
- 「楽しかった」だけで止めず、**具体的な日・具体的な写真**を思い出させる
- 止まった人には、止まった日のお題を一緒に見ながら聞く

---

## 質問

### Q1（アイスブレイク兼、自発性の観測）

> この2週間、どうでした？

**H-2 の判定はここでほぼ決まる。**
この質問に対して、**こちらから聞く前に**「他の人の写真」の話が出たかどうかを記録する。

| 記録欄 | |
| --- | --- |
| 自発的に他人の投稿に言及したか | ☐ はい ☐ いいえ |
| 出てきた言葉（原文で） | |

### Q2

> 投稿したあと、他の人の写真って見ました？

- 見た → **どの日のが印象に残ってる？**（具体的な日が出るか）
- 見ていない → **なぜ見なかった？**（見る導線が無い / 興味が無い / 気づかなかった、のどれか）

### Q3

> 逆に、自分の写真に反応が付いたときってどうでした？

仕様書 [D-07](../SPEC.md#d-07-通知は1日最大2回)（リアクションまとめ通知が唯一のソーシャル報酬）の検証。
反応が嬉しかったという声が出ないなら、投稿の動機が続かない可能性が高い（[R-09](../SPEC.md#15-リスク登録簿)）。

### Q4 — 続いた人へ

> 毎日出すのって、しんどくなかったですか？

- しんどかった日はどれか
- それでも続いたのはなぜか（**義理か、面白さか**を見分ける。義理なら数字は嘘）

### Q5 — 止まった人へ

> 止まった日、覚えてますか？

その日のお題を見せながら聞く。

- お題が難しかった / 忙しかった / 飽きた / 見るものが無かった、のどれか
- **一度止まったあと、戻ろうと思った瞬間はあったか**（あれば、それが通知設計のヒント）

### Q6（最後に一度だけ聞く）

> このアプリ、もし本当にあったら使いますか？

**この答えは信用しない。** 全員が「使う」と言う。
Q1 の自発的な言及と、実際の出席データ（`attendance.csv`）だけを判断材料にする。

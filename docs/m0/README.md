# M0 検証キット

> **目的：アプリを作る前に、「お題があれば人は毎日投稿するか」を2週間・コストほぼゼロで確かめる。**
> 仕様書 [§4](../SPEC.md#4-検証状況これが最優先) の実行キット。

---

## 0. これは何のためのものか

ODAI の中核にある賭けは一点だけ。

> **お題そのものが、毎日アプリを開く理由になる。**

ここが外れていると、ゲーティングも通知もリアクションも意味がない。
Poparazzi は「承認欲求を消したら、開く理由も一緒に消えた」ことで死んだ（[§3](../SPEC.md#3-競合と前例)）。

したがって、**実装より先にこの2週間をやる。** これが v1.1 で最も重要な決定。

---

## 1. 判定基準（先に決めておく）

集計してから基準を動かさないために、**開始前に**この表を確定させる。

| 仮説 | 測るもの | Go 基準 |
| --- | --- | --- |
| **H-1** | 初日に投稿した人のうち、14日目にも投稿した人の割合 | **≥ 20%** |
| **H-2** | 「他の人の見るのが楽しい」と**自発的に**言った人（n=10 のヒアリング） | **≥ 5人** |
| **H-3** | 日別参加率の 最大 ÷ 最小 | **≥ 1.5倍** |

### 判定の読み方

| 結果 | 意味 | 次にやること |
| --- | --- | --- |
| H-1 ○ / H-2 ○ | 賭けは成立している | M1（クローズドβ）へ進む |
| H-1 ○ / H-2 ✗ | 投稿は続くが、閲覧が退屈 | フィード設計（[§6.3](../SPEC.md#63-フィード)）を作り直してから M1 |
| H-1 ✗ / H-2 ○ | 見るのは楽しいが、毎日は出せない | お題の負荷を下げる。[§7.2](../SPEC.md#72-採用基準撮影可能性テスト) の基準を厳しくして再検証 |
| **H-1 ✗ / H-2 ✗** | **お題では毎日開かせられない** | **実装に進まない。** コンセプトから設計し直す |
| H-3 ✗ | お題の良し悪しで差が出ない | お題は改善レバーにならない。差別化を別の場所に置く必要がある |

> H-3 が ✗ の場合は特に注意。ODAI は「お題の質」を唯一の差別化にしているので、
> それが参加率を動かさないなら、プロダクトの前提が崩れる。

## 2. 準備（開始3日前まで）

### 2.1 場を用意する

LINEオープンチャット / Discord サーバー / Slack のどれか1つ。**新規に作る**（既存コミュニティに相乗りしない）。

- 写真が投稿でき、リアクションが押せること
- 過去の投稿がスクロールで遡れること
- 参加者が**互いの投稿を見られる**こと（H-2 の検証に必須）

### 2.2 人を集める（目標 50〜100人）

- ターゲット（16〜28歳）に近い人だけを入れる。身内の大人だけで埋めない
- **50人を下回る場合は日程をずらしてでも集める。** 20人だと、日々の参加人数のブレが大きすぎて H-3 が読めない
- 集めた人は全員 [`attendance.csv`](attendance.csv) に1行ずつ登録しておく

### 2.3 募集文（コピペ用）

```
📷 2週間だけの実験に参加してくれる人を探しています

毎朝ひとつ「お題」が出ます。
やることは、それに写真1枚で答えるだけ。

・1日1枚だけ
・いま撮った写真でOK（きれいじゃなくていい）
・コメントは任意
・見るだけの日があっても大丈夫

新しいアプリを作る前の実験です。
2週間だけ、付き合ってくれませんか。
```

### 2.4 やらないこと

- 「毎日必ず投稿してね」と**お願いしない**（お願いで動いた参加は、プロダクトの参加ではない）
- 投稿が少ない日に**運営が煽らない**（その日の参加率の低さは、お題が悪いという貴重なデータ）
- お題を当日に思いつきで変えない（[`prompts.md`](prompts.md) の14本を順番通りに出す）

## 3. 毎日のオペレーション

| 時刻 | やること |
| --- | --- |
| 8:00 | [`prompts.md`](prompts.md) からその日のお題をコピペして投稿 |
| 随時 | 参加者の投稿にリアクションが付いているかを観察（運営は押さない） |
| 24:00 | その日の投稿者を [`attendance.csv`](attendance.csv) に記録し、[`daily-log.csv`](daily-log.csv) に気づきを書く |

### 記録のコツ

- **参加＝写真を投稿した人だけ**。スタンプだけ、コメントだけは参加に数えない
- 締切後の投稿（遅刻投稿）は `attendance.csv` では参加に数えず、`daily-log.csv` の `late` 列に人数だけ書く
  （仕様書 [U-06](../SPEC.md#17-未決事項)「遅刻投稿を許すか」の判断材料になる）
- 「投稿しようとして、やめた」人がいたら必ずメモする。**お題が難しいという最重要のシグナル**

## 4. 集計

```bash
python3 docs/m0/report.py
```

`attendance.csv` と `daily-log.csv` を読んで、H-1 / H-3 の判定、日別参加率、
お題ランキング、継続曲線を出力する。**毎日実行してよい**（途中経過が見える）。

```bash
# 別のディレクトリのデータを使う場合
python3 docs/m0/report.py --dir path/to/data

# 動作確認用のダミーデータで試す
python3 docs/m0/report.py --demo
```

## 5. H-2 のヒアリング

12日目〜14日目に、**10人**に話を聞く（[`interview.md`](interview.md) の台本を使う）。

- 参加が続いた人5人、途中で止まった人5人の**両方**から聞く
- 止まった人の話の方が価値が高い。「なんとなく」で終わらせず、止まった日のお題を一緒に見る

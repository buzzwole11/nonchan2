# M0 配信文（14日分）

**使い方**：毎朝8:00に、その日のブロックをそのままコピーして投稿する。
お題は順番通りに出す（当日に思いつきで差し替えない）。

各お題のリアクションは、仕様書 [D-04](../SPEC.md#d-04-リアクションはお題ごとに変わる)
（お題ごとに絵文字が変わる）の検証を兼ねている。**リアクションも毎日変えて出すこと。**

---

## Day 1 — 初日だけ、説明を付ける

```
おはようございます。今日から2週間、毎朝ひとつ「お題」を出します。

📷 今日のODAI

「今日の机」

やることはこれだけです。
・写真1枚で答える
・いま撮った写真でお願いします（カメラロールから選ばない）
・ひとことは任意、30文字くらいまで
・他の人の写真には 👏 🫠 📚 ✨ のどれかでリアクションを

きれいじゃなくて大丈夫です。散らかっててもそのままで。
締切は今日の24:00。投稿できない日があっても気にしないでください。
```

## お題の設計意図（運営用メモ・参加者には見せない）

| Day | お題 | この日で見たいこと |
| --- | --- | --- |
| 1 | 今日の机 | 撮影のハードルが最も低い。初日の投稿率がここで出なければ、以降は伸びない |
| 2 | 今飲んでいるもの | 結果が全員バラバラになるか（一覧で見て面白いか＝H-2） |
| 3 | 充電残量を見せて | **「正解が無いお題」の代表格。** 参加率が跳ねるはずの日 |
| 4 | 今あなたの右側にあるもの | 場所非依存の検証。外出中の人でも撮れるか |
| 5 | 今日いちばん触ったもの | 全員スマホになる想定。**「答えが被る」ことが笑いになるか** |
| 6 | 一番使っているペン | 持っていない人が出る（＝除外される人がいるお題の悪さを測る） |
| 7 | 今日これと戦う | v1.0 の「今日の敵」を具体化した改稿版。抽象語の改稿が効くかの検証 |
| 8 | 今日の足元 | 人が写り込むお題。安全面の反応を見る |
| 9 | いま手が届く場所にある本 | 本が無い人が出る。Day 6 と合わせて「除外率」を測る |
| 10 | 今日の空 | **屋外に出る必要がある＝負荷が高い。** ここで落ちるかを見る |
| 11 | いちばん古くから使っているもの | 探す時間が必要（30秒テストの境界線）。負荷の上限を測る |
| 12 | 今日食べたいちばん美味しかったもの | 夜まで投稿が遅れるお題。締切前の駆け込みが起きるか |
| 13 | 机の上でいちばん邪魔なもの | 自虐系。**リアクションが最も多く付くはずの日**（H-2 の山場） |
| 14 | 今日おつかれさまの1枚 | 自由度が高い＝抽象的。最終日にあえて置いて、抽象お題の弱さを確認 |

> **Day 3・Day 13 が最高、Day 10・Day 11 が最低**になる想定で組んである。
> この差が **1.5倍以上**つけば H-3 が成立する（＝お題は改善できる変数だと確認できる）。
> 想定と違う日が跳ねた／沈んだ場合、その理由の方が仕様書より価値がある。必ずメモすること。
